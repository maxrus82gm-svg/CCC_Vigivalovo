## Владелец и разрешения

Git полностью контролирует пользователь. Если задача не разрешает Git, агент не выполняет даже команды чтения.

При прямом разрешении на чтение допустимы: `git status`, `git log`, `git show`, `git diff`, `git branch --show-current` и чтение GitHub через API или коннектор.

Без отдельной прямой команды запрещены: commit, push, pull, fetch, merge, rebase, reset, clean, checkout, switch, создание или удаление веток и тегов, изменение remote, Git-конфига и истории.

## Свежая проверка GitHub

Перед review или задачей, требующей удалённого состояния:

1. Получить актуальную ветку непосредственно из GitHub.
2. Получить последний commit по актуальному ref.
3. Зафиксировать полный SHA и фактический message без исправлений.
4. Получить список файлов этого commit.
5. Читать важные удалённые файлы по зафиксированному SHA или актуальному ref.
6. Не использовать старый скриншот, открытую страницу, кэш или прежний результат.
7. Если ожидаемый commit отсутствует, писать `push не обнаружен`.
8. Если GitHub недоступен, писать `удалённый commit не подтверждён`.
9. Для Issue или Pull Request заново получить комментарии и не считать старую копию актуальной.
10. В отчёте указать фактически прочитанные SHA и message.

## Формат проверки

Проверка после отчёта начинается с:

```text
СТАТУС КОММИТА
GIT / ПРОВЕРКА РЕПОЗИТОРИЯ
```

Служебные изменения вне scope перечисляются как неожиданные, а не выдаются за неизменённые. Если область не проверялась, так и писать.
