# Правила использования субагентов

[[Карта_агентской_документации]] · [[Список_правил]] · [[Правила_агентского_цикла]] · [[Настройка_прав_субагентов]] · [[Отчёт_субагента]]

## Ответственность

Основной агент принимает финальное решение, задаёт scope, проверяет результат и отвечает перед пользователем. Субагент выполняет только ограниченную подзадачу и не расширяет полномочия.

## Когда делегировать

Безопасно рассматривать read-only разведку, поиск, сравнение документов, черновик, проверку Markdown, UTF-8, placeholders и независимое review. Делегирование полезно, когда оно экономит ресурсы или повышает качество без потери контроля.

Не делегировать финальное инженерное решение, рискованные правки, неограниченный scope, операции Git и изменения служебных конфигов.

## Маршруты

- Локальный управляемый агент получает короткий явный scope через `{{LOCAL_AGENT_ROUTE}}`; основной агент наблюдает и проверяет результат.
- Внешний агент через чат пользователя получает задачу только после заполнения [[Задача_внешнему_субагенту]]. Пользователь переносит сообщение, а основной агент не имитирует внешний запуск.
- Резервный режим без рабочего документа допустим только при явном разрешении пользователя и запрете на изменение документа задачи; это фиксируется в отчёте.

## Ограничения

- Не использовать Git без прямого разрешения.
- Не менять файлы вне scope, `.git`, `.obsidian` и реальные конфиги агентов.
- Не обновлять и не очищать БЛОКИ 1–3 главной TASK; это обязанность основного Агента.
- Не доверять субагенту финальную проверку.
- Завершать понятным статусом, перечнем сделанного, проверок и проблем.
