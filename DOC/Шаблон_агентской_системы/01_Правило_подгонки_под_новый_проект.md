# Правило подгонки под новый проект

Версия шаблона: **0.4**.

## Главный принцип

Шаблон остаётся отдельным источником-примером. Агент не копирует этот каталог в новый проект, а создаёт на его основе самостоятельные документы внутри `{{OBSIDIAN_VAULT}}`.

## Порядок

1. Прочитать документы в порядке из [[Как_переносить_агентскую_систему]].
2. Инвентаризировать рабочий Vault до создания, удаления или переименования файлов.
3. Сопоставить каждый шаблонный документ не более чем с одним рабочим документом того же назначения.
4. Обновить или переименовать существующий документ вместо создания дубля.
5. Создать недостающие рабочие документы и заменить placeholders проверенными значениями.
6. Для неизвестных значений использовать `НЕ УКАЗАНО`.
7. Не добавлять в рабочие документы ссылки на шаблон как на действующее правило.
8. Не синхронизировать рабочие документы и шаблон автоматически.
9. Проверить результат по [[03_Чеклист_проверки_переноса]].

## Обязательная архитектура цикла

- большая TASK после публикации заморожена до отчёта;
- каждая новая TASK запускается отдельным малым сообщением;
- поздние уточнения передаются малыми сообщениями и действуют только на затронутую часть;
- главный документ хранит только активную TASK, последний отчёт и последний REVIEW / статус;
- БЛОКИ 1–3 имеют единые разделители и разные цветовые маркеры: синий, зелёный и жёлтый;
- постоянные правила вынесены к каноническим владельцам;
- граф строится как `Старт → тематическая карта → каноническое правило → дочерний документ`;
- служебный список владельцев не дублирует тематическую карту набором wiki-links.

## Запрещено

- копировать папку шаблона целиком;
- превращать паспорт шаблона в паспорт конкретного проекта;
- оставлять обязательные placeholders в рабочих документах;
- переносить реальные данные проекта в универсальные примеры;
- создавать вторую параллельную систему правил;
- менять Git, `.obsidian`, код или конфиги без прямого разрешения.
