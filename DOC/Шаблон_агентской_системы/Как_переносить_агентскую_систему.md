# Как переносить агентскую систему

Версия шаблона: **0.3**.

Этот каталог — отдельный универсальный источник-пример. Он не является рабочей документацией какого-либо проекта и не включается в обычную карту чтения агента.

## Архитектурное правило

- Не копировать каталог `Шаблон_агентской_системы` целиком в рабочий Vault.
- Читать его только по прямой задаче пользователя на создание, перенос или обновление агентской документации.
- Создавать в рабочем Vault самостоятельные документы по одному документу одного назначения на каждый нужный шаблон.
- Подставлять в рабочие документы реальные значения проекта; неизвестные значения обозначать `НЕ УКАЗАНО`.
- Не оставлять в рабочих документах обязательные к заполнению placeholders.
- Не ссылаться из рабочих документов на шаблон как на действующее правило.
- Не переносить изменения между шаблоном и рабочими документами автоматически в любом направлении.
- Изменять шаблон только по отдельной прямой задаче пользователя.

## Порядок создания рабочего комплекта

1. Заполнить паспорт значениями проекта, не изменяя placeholders в этом каталоге.
2. Проверить рабочий Vault и найти документы того же назначения.
3. Обновить или безопасно переименовать существующий документ вместо создания дубля.
4. Создать только недостающие самостоятельные рабочие документы.
5. Назначить каждому правилу одного канонического владельца.
6. В маршрутизаторах оставить краткое резюме и wiki-link, а не копию правила.
7. Добавить согласованный YAML frontmatter и осмысленные wiki-links.
8. Проверить Base, UTF-8, кириллицу, ссылки, placeholders и запрещённый scope.
9. Записать итоговый отчёт.

## Постановка задач

Канонические формы находятся в:

- [[Большой_блок_задачи]]
- [[Малый_блок_задачи]]
- [[Задача_агенту]]

Большой блок — полная постановка задачи одним непрерывным фрагментом. Малый блок — отдельное короткое сообщение после размещения большого блока. Позднее уточнение не расширяет scope молча, не отменяет Git-политику и при конфликте останавливает только спорную часть.

## Безопасность

Git контролирует пользователь. Без прямой команды запрещены операции, меняющие репозиторий или удалённое состояние. Служебные настройки Obsidian и реальные конфиги агентов не изменяются без прямого разрешения.

Все Markdown-файлы сохраняются как UTF-8 с настоящими переносами строк и неповреждённой кириллицей.
