# Правила агентского цикла

Родительская ветвь: `Карта_агентской_документации`.

## Назначение

Этот документ — канонический владелец ролей, режимов, заморозки опубликованной TASK, жизненного цикла работы и REVIEW Ассистента.

Публикацией TASK и обновлением БЛОКОВ 1–3 владеют [[Правила_запуска_задач]]. Git-политикой и удалённой проверкой владеют [[Правила_Git_и_проверки]]. Локальным режимом владеет документ `Правила_локальной_работы_агента`. Форматом результата владеет [[Отчёт_агента]].

## Роли

### Пользователь

- принимает конечные и архитектурные решения;
- управляет Git и разрешает потенциально опасные действия;
- публикует большую TASK и передаёт малый стартовый блок либо отправляет самостоятельную небольшую задачу;
- передаёт итоговый отчёт Агента Ассистенту;
- подтверждает закрытие результата или начало следующего цикла.

### Ассистент ChatGPT

- помогает Пользователю сформулировать цель и границы;
- выбирает между большим циклом и самостоятельной небольшой задачей по [[Правила_запуска_задач]];
- подписывает тип каждого блока снаружи copy-paste области;
- для большого цикла создаёт одну компактную большую TASK и отдельный обязательный малый стартовый блок;
- до отчёта передаёт изменения только малыми уточнениями, не переписывая TASK;
- после отчёта сначала проверяет доступное актуальное удалённое состояние репозитория, затем выполняет REVIEW фактического результата;
- рекомендует принятие, малую корректировку, новую TASK или откат Пользователем;
- не начинает новую большую TASK до завершения решения по предыдущему циклу.

### Локальный Агент

- в большом цикле читает обязательный минимум и активную TASK, а в самостоятельной небольшой задаче следует полученному малому блоку;
- выполняет только разрешённый scope и не расширяет архитектуру самостоятельно;
- применяет позднее уточнение только к явно затронутой части;
- выполняет разрешённые локальные проверки;
- записывает итоговый отчёт и предварительный статус;
- не объявляет результат принятым и не подменяет REVIEW Ассистента.

### Субагенты

- получают только ограниченную часть scope;
- не получают полномочий основного Агента на закрытие TASK;
- возвращают результат основному Агенту, который его перепроверяет и отвечает перед Пользователем.

## Режимы выполнения

### Ограниченный

Реализация и точные границы заданы заранее. При неоднозначности Агент останавливает спорную часть и не выбирает альтернативную архитектуру.

### Самостоятельный

Цель, ограничения и критерии заданы, а Агент самостоятельно исследует связанные локальные файлы и выбирает безопасный способ реализации внутри scope.

Режим указывается в TASK. Если он не указан, применяется самостоятельный режим без права расширять scope или постоянные правила.

## Замороженная большая TASK

После публикации большой TASK и до итогового отчёта БЛОК 1 заморожен. Нельзя задним числом переписывать, заменять или редактировать требования и критерии готовности.

Все последующие указания передаются отдельными малыми сообщениями в чат Агента. Более позднее явное уточнение имеет приоритет только для затронутой части. Если противоречие нельзя разрешить однозначно, Агент останавливает только спорную часть и фиксирует проблему.

## Жизненный цикл

Ассистент сначала выбирает форму задачи по [[Правила_запуска_задач]]. Большой цикл и самостоятельная небольшая задача — два допустимых пути.

### Большой цикл

1. Пользователь и Ассистент определяют цель нового цикла.
2. Ассистент формирует компактную большую TASK и отдельный малый стартовый блок.
3. Пользователь публикует TASK в БЛОКЕ 1 документа `Задача_агенту`.
4. Пользователь отправляет малый стартовый блок Агенту; без него TASK не запущена.
5. Агент выполняет TASK локально по постоянным и тематическим правилам.
6. Новые уточнения до отчёта приходят только малыми сообщениями и не меняют текст БЛОКА 1.
7. Агент записывает последний отчёт в БЛОК 2 и последний предварительный статус в БЛОК 3.
8. При полном выполнении Агент очищает содержимое БЛОКА 1 и оставляет состояние ожидания. При частичном выполнении или блокировке TASK сохраняется.
9. Пользователь передаёт отчёт Ассистенту и при необходимости самостоятельно выполняет разрешённые Git-действия.
10. Ассистент выполняет REVIEW отчёта и фактического результата согласно доступным разрешениям.
11. По REVIEW принимается решение: закрыть цикл, уточнить частично выполненную и всё ещё активную TASK малым сообщением либо начать новую TASK.

### Самостоятельная небольшая задача

1. Ассистент выдаёт подписанный снаружи `МАЛЫЙ БЛОК — НЕБОЛЬШАЯ ЗАДАЧА`.
2. Пользователь отправляет цельный copy-paste блок прямо в чат Агента.
3. Агент выполняет короткую работу в указанном scope, проверяет результат и возвращает краткий отчёт в чат.
4. БЛОКИ 1–3 не изменяются, если это прямо не потребовано задачей.
5. Пользователь передаёт отчёт Ассистенту для обычного REVIEW.

## Контрольная точка отчёта и REVIEW

Итоговый отчёт завершает локальный этап, но не означает принятие результата. В большом цикле БЛОК 3 до REVIEW содержит предварительный статус Агента; после REVIEW Ассистент заменяет его одним актуальным решением.

После получения отчёта по текущему проекту Ассистент сначала выполняет обязательную удалённую проверку по [[Правила_Git_и_проверки]], если репозиторий доступен. Ответ начинается с явного статуса удалённого commit. Источниками истины являются актуальный commit, diff и фактические файлы, а не текст отчёта. Недоступная или непроверенная область обозначается явно.

Завершённая TASK не переписывается задним числом. Если при полном выполнении БЛОК 1 уже очищен, любое следующее изменение считается новой задачей: Ассистент выбирает для неё новый большой цикл либо самостоятельный малый блок по масштабу. Малое уточнение старой TASK допустимо только когда она сохранена из-за частичного выполнения или блокировки.

## Изменение постоянных правил

Постоянное правило изменяется только по отдельной TASK, основанной на решении Пользователя. История изменений хранится средствами, которыми управляет Пользователь; отдельный документ истории не создаётся.
