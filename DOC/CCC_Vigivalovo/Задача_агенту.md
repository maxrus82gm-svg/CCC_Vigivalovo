# ГЛАВНЫЙ ПРИОРИТЕТ — ЖИЗНЕННЫЙ ЦИКЛ ЗАДАЧИ

После анализа привести CCC_Vigivalovo к следующему однозначному циклу.

## 1. Новая большая задача

Ассистент ChatGPT формирует одну большую TASK.

Большая TASK помещается в:

`БЛОК 1 — ТЕКУЩАЯ ЗАДАЧА`

главного рабочего документа.

После публикации большая задача считается зафиксированной.

До получения итогового отчёта Агента она:

- не переписывается;
    
- не заменяется;
    
- не редактируется из-за каждого нового уточнения.
    

---

## 2. Обязательный малый стартовый блок

После каждой новой большой задачи Ассистент обязательно выдаёт отдельный малый блок для чата Агенту.

Малый стартовый блок:

- сообщает, что большая задача опубликована;
    
- приказывает её прочитать;
    
- запускает выполнение;
    
- может содержать короткую оперативную ремарку.
    

Большая задача без стартового малого блока считается ещё не запущенной.

---

## 3. Уточнения во время выполнения

Пока итоговый отчёт Агента не получен, все новые указания передаются только отдельными малыми сообщениями в чат Агенту.

Через малое сообщение можно:

- уточнить требование;
    
- раскрыть пункт;
    
- изменить отдельное решение;
    
- отменить отдельный пункт;
    
- добавить небольшое требование.
    

Большую TASK при этом не переписывать.

Более позднее явное уточнение Пользователя имеет приоритет только для затронутой части задачи.

Если возникает конфликт, который нельзя разрешить однозначно, Агент останавливает спорную часть и фиксирует проблему.

---

## 4. Завершение работы Агентом

Если задача выполнена полностью, Агент:

1. записывает итоговый отчёт в БЛОК 2;
    
2. обновляет БЛОК 3;
    
3. полностью удаляет выполненную TASK из БЛОКА 1;
    
4. переводит БЛОК 1 в состояние ожидания.
    

Смысл состояния:

`Активная задача отсутствует.`

`Статус: ожидается новая задача от Пользователя.`

Главный рабочий документ не является архивом выполненных TASK.

В нём хранится только:

- текущая активная задача;
    
- последний отчёт;
    
- последний статус.
    

Если задача выполнена частично или требует решения Пользователя — БЛОК 1 не очищать.

---

## 5. REVIEW Ассистента

После того как Пользователь передал Ассистенту итоговый отчёт Агента, старый цикл считается завершённым со стороны выполнения.

Ассистент переходит в режим REVIEW.

Ассистент:

- читает отчёт;
    
- при необходимости проверяет GitHub;
    
- сверяет фактический результат;
    
- сообщает Пользователю состояние;
    
- не продолжает старую TASK через новые большие блоки.
    

После REVIEW принимается решение:

- задача закрыта;
    
- требуется небольшая корректировка;
    
- начинается новая большая TASK.

# РОЛИ

В документации должно быть однозначно видно разделение ответственности.

## Пользователь

Пользователь:

- принимает конечные решения;
    
- управляет Git;
    
- разрешает потенциально опасные операции;
    
- передаёт отчёт Агент → Ассистент;
    
- подтверждает начало нового цикла.
    

## Ассистент ChatGPT

Ассистент:

- помогает Пользователю формулировать задачу;
    
- создаёт большую TASK;
    
- после неё создаёт обязательный малый стартовый блок;
    
- до отчёта выдаёт изменения только малыми блоками;
    
- после отчёта выполняет REVIEW;
    
- формирует следующую большую TASK только после завершения предыдущего цикла.
    

## Локальный Агент

Агент:

- читает опубликованную TASK;
    
- соблюдает канонические правила;
    
- выполняет разрешённый scope;
    
- не расширяет задачу самостоятельно;
    
- пишет итоговый отчёт;
    
- правильно закрывает БЛОК 1;
    
- не управляет Git без прямого разрешения.
    

## Субагенты

Субагенты работают только в пределах делегированного scope.

Основной Агент отвечает за их результат и перепроверяет его.
