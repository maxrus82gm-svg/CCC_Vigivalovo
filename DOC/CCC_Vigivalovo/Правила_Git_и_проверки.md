## Политика

Git полностью контролирует пользователь. Если текущая задача не разрешает Git, агент не выполняет даже команды чтения.

GitHub предназначен прежде всего для C++ исходников, текстовой конфигурации и проектной документации. Тяжёлые бинарные Unreal assets, сгенерированные данные, кэши и локальное состояние инструментов остаются локально; каноническим источником конкретных ignore-patterns является корневой `.gitignore`.

При прямом разрешении на чтение допустимы:

- `git status`
- `git log`
- `git show`
- `git diff`
- `git branch --show-current`
- чтение GitHub через API или подключённый коннектор

Без отдельной прямой команды пользователя запрещены commit, push, pull, fetch, merge, rebase, reset, clean, checkout, switch, создание или удаление ветки и тега, изменение remote, Git-конфига и истории.

## Свежая удалённая проверка

Перед review или задачей, зависящей от GitHub:

1. Получить актуальную ветку непосредственно из GitHub.
2. Получить последний commit по актуальному ref.
3. Записать полный SHA и фактический message без исправлений.
4. Получить список файлов этого commit.
5. Читать важные удалённые файлы по зафиксированному SHA или актуальному ref.
6. Не использовать старые скриншоты, открытые страницы, кэш и прежние результаты как доказательство.
7. Если ожидаемый commit отсутствует, писать `push не обнаружен`.
8. Если GitHub недоступен, писать `удалённый commit не подтверждён`.
9. Для Issue или Pull Request заново получать актуальные комментарии.
10. В отчёте указывать фактически проверенные SHA и message.

## REVIEW Ассистента

Итоговый отчёт Агента запускает REVIEW, но не заменяет проверку фактического результата. Ассистент использует GitHub только когда Пользователь разрешил внешний доступ и соответствующую проверку. При отсутствии разрешения удалённая область помечается как непроверенная.

Формат REVIEW находится в [[Отчёт_проверки]]. Проверка начинается с:

Review начинается с:

```text
СТАТУС КОММИТА
GIT / ПРОВЕРКА РЕПОЗИТОРИЯ
```

Изменения служебных файлов вне scope перечисляются как неожиданные. Непроверенная область обозначается `не проверялось`. Решение после REVIEW принимается по [[Правила_агентского_цикла]].
