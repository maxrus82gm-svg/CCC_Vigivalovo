# Правила запуска задач

Родительская ветвь: `Карта_агентской_документации`.

## Назначение

Этот документ — канонический владелец выбора формы задачи, публикации большой TASK, обязательного малого запуска, самостоятельных малых задач, поздних малых уточнений, внешних подписей блоков и обновления БЛОКОВ 1–3.

Роли, режимы, жизненный цикл и REVIEW определяет [[Правила_агентского_цикла]].

## Дочерние документы

- [[Задача_агенту]] — активная большая TASK, последний отчёт и последний REVIEW / статус.
- [[Большой_блок_задачи]] — форма большой TASK; из неё открывается форма малого блока.

## Выбор формы задачи

Не каждая работа требует большой TASK в Obsidian. Ассистент выбирает форму по масштабу работы и необходимости сохранять постановку до итогового отчёта.

Большая TASK нужна, если работа:

- имеет заметный scope или несколько этапов;
- требует длительного цикла;
- должна быть зафиксирована в БЛОКЕ 1;
- содержит важные ограничения, проверки или критерии завершения;
- требует неизменного сохранения постановки до итогового отчёта.

Самостоятельная небольшая задача может быть передана только малым блоком прямо в чат Агента, если работа короткая и однозначная, легко проверяется и не требует полноценного большого цикла. Большая TASK не создаётся, когда её отдельная фиксация добавляет больше бюрократии, чем пользы.

Самостоятельный малый блок не используется для обхода активной большой TASK. Если сообщение относится к активной TASK, оно считается её запуском или уточнением и подчиняется правилам замороженного БЛОКА 1.

## Внешняя подпись copy-paste блока

Ассистент всегда размещает служебную подпись типа **снаружи** цельного copy-paste блока. Пользователь должен сразу видеть, куда вставлять текст. Подпись не входит в копируемое содержимое.

Используются подписи по смыслу:

- `БЛОК 1 — БОЛЬШАЯ ЗАДАЧА` — перед текстом для БЛОКА 1;
- `МАЛЫЙ БЛОК — ЗАПУСК` — перед стартовым сообщением в чат Агента;
- `МАЛЫЙ БЛОК — УТОЧНЕНИЕ` — перед уточнением активной TASK;
- `МАЛЫЙ БЛОК — НЕБОЛЬШАЯ ЗАДАЧА` — перед самостоятельной малой задачей.

## Большой цикл: два обязательных сообщения

Для каждого нового большого цикла Ассистент готовит два отдельных сообщения:

1. большую TASK для БЛОКА 1 документа `Задача_агенту`;
2. малый стартовый блок для чата Агента.

Большая TASK без отдельного малого стартового блока считается опубликованной, но ещё не запущенной.

## Компактная большая TASK

Большая TASK содержит преимущественно уникальную информацию текущей работы:

- название, цель и специфический контекст;
- режим выполнения;
- разрешённый scope;
- нестандартные запреты и особые разрешения;
- проверки именно этой задачи;
- критерии готовности;
- специальные требования к отчёту.

Стандартный жизненный цикл, роли, Git-политика, локальный режим, UTF-8, документация, субагенты и стандартный формат отчёта не копируются полностью. TASK ссылается на соответствующие канонические документы и уточняет только отклонения.

После публикации большая TASK замораживается по правилам агентского цикла.

## Малый стартовый блок

Стартовый блок:

- сообщает, что большая TASK опубликована;
- указывает путь к документу `Задача_агенту`;
- приказывает полностью прочитать БЛОК 1 и начать выполнение;
- напоминает ключевое ограничение текущей работы;
- требует итоговый отчёт.

Он не повторяет полную TASK и не расширяет её scope.

## Малые уточнения

До итогового отчёта по активной большой TASK все относящиеся к ней новые указания передаются отдельными короткими сообщениями в чат Агента. Уточнение может раскрыть, дополнить, изменить или отменить только отдельный пункт.

Позднее уточнение применяется только к явно затронутой части. Остальной scope сохраняется. Новое разрешение на Git, сеть, удаление или другую опасную операцию должно быть прямым и однозначным.

## Самостоятельная небольшая задача

Самостоятельный малый блок содержит цель, разрешённый scope, важные ограничения, способ проверки и требование краткого отчёта. Он передаётся напрямую в чат Агента и сам запускает работу.

Такая задача не создаёт большую TASK, не меняет БЛОК 1 и не требует обновления БЛОКОВ 1–3, если Пользователь явно не указал иное. Результат возвращается кратким отчётом в чат.

## Обновление БЛОКОВ 1–3

Главный документ визуально разделяет крупные области едиными линиями и цветными маркерами:

- `🟦 БЛОК 1` — активная TASK;
- `🟩 БЛОК 2` — последний отчёт Агента;
- `🟨 БЛОК 3` — REVIEW / статус.

Оформление остаётся компактным и не требует CSS, изменения `.obsidian` или управления координатами графа.

В большом цикле при полном выполнении Агент:

1. записывает краткий фактический отчёт в БЛОК 2;
2. заменяет БЛОК 3 одним последним предварительным статусом;
3. полностью удаляет выполненную TASK из БЛОКА 1, сохраняя заголовок;
4. оставляет в БЛОКЕ 1 только:

```text
Активная задача отсутствует.

Статус: ожидается новая задача от Пользователя.
```

При частичном выполнении, ошибке, блокировке или необходимости решения Пользователя БЛОК 1 не очищается. Отчёт и статус описывают фактический результат без заявления о полном завершении.

БЛОК 2 хранит только последний отчёт. БЛОК 3 хранит только последний REVIEW / статус. Документ `Задача_агенту` не является архивом старых TASK.
