# Правила создания документов

[[Карта_агентской_документации]] · [[Список_правил]]

## Названия и дубли

- Пользовательские документы называются по-русски.
- Технические имена Unreal Engine, C++, Git, конфигов, форматов и внешних инструментов сохраняются, если от них зависит работа инструмента.
- До создания файла проверяется существующий документ того же назначения.
- Существующий документ обновляется или переименовывается вместо создания дубля.
- Каждое правило имеет одного канонического владельца; маршрутизаторы дают ссылку и краткое резюме.

## UTF-8 и кириллица

1. Перед изменением прочитать файл и проверить кодировку.
2. Markdown сохранять как UTF-8 с настоящими переносами строк.
3. Кириллические имена не транслитерировать автоматически.
4. Не записывать файл одной строкой и не использовать буквальную последовательность `\n` вместо переноса.
5. Не добавлять лишние обратные слэши в готовые Windows-пути.
6. При повреждённой кодировке остановить изменение конкретного файла и записать проблему.
7. После записи повторно прочитать файл и проверить русский текст.
8. После переименования проверить фактическое имя, дубли по регистру и все ссылки.

## Obsidian

- Каждый документ агентской системы имеет единый frontmatter: `проект`, `тип`, `раздел`, `статус`, `источник`.
- Граф строится по иерархии: [[Старт]] → тематическая карта → рабочий документ.
- Каждый рабочий документ имеет осмысленный путь к [[Карта_агентской_документации]] или другой тематической карте; прямая ссылка каждого файла на [[Старт]] не требуется.
- Wiki-links ведут только к существующим связанным документам; самоссылки и бессмысленные связи запрещены.
- Рабочие документы не ссылаются на внешние примеры как на действующие правила.
- Base отбирает документы по frontmatter и создаётся только по подтверждённому синтаксису.
- `DOC/CCC_Vigivalovo/.obsidian` не изменяется без прямого разрешения.

Тематическая карта создаётся только для реально существующей группы материалов. Пустые карты будущих C++ систем, механик или исследований заранее не создаются.
